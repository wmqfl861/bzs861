# 持久批读的共享请求与取消

本增量推进 `CACHE-01 / B-24 / FT-032`，范围限定为 `read_many.submit` 创建的持久静态网页读取任务。普通 `web.read`、map/crawl、来源搜索以及不同 owner 不进入这条合并通道。现有 HTTP、CLI、MCP 批读和任务控制接口保持一致，业务仍由 C++ 核心执行。

## 合并范围

核心派发某个批读项时，在同一个 SQLite 写事务中寻找已经排队的其他任务。每组最多 32 个成员；每个任务只取自己的第一个待处理项。匹配必须同时满足：

- owner、主体权限代际、任务创建时的删除序号，以及目标 URL 删除代际相同；
- 精确规范化 URL 相同，不使用搜索去重键，不合并协议、路径或查询参数不同的请求；
- 每页有效超时相同，订阅任务的期限覆盖本次物理请求租约；
- 每个订阅者的剩余请求/字节额度至少覆盖付款任务本次获准的上限；
- 任务仍可派发，目标项没有耗尽显式尝试次数。

所有成员在此事务内捕获同一当前快照和发布序号。各自保留独立的任务/项状态、权限代际和租约代数。请求开始后的新任务不加入已派发的组；它会在后续轮次取得自己的请求机会。因此本实现是有界的合并派发，并不宣称通用的任意时刻在途合并或完整 B-24 验收。

## 物理请求与账本

最先取得调度机会的任务是固定付款任务。只有它预留请求和字节预算，向 Worker 发送一个 `attempt_id`。其他成员是订阅者，不再重复预留或计费，也不会凭合并扩大付款任务的出站上限。

schema13 的 `read_shared_attempts` 保存物理请求、固定付款任务、原始预留、成员总数和已知/未知结算；`read_shared_members` 保存每次尝试的成员关系。已有 `read_job_items` 继续保存每个成员自己的尝试和发布状态。显式重试产生新的尝试，不改写此前的共享请求账本。

Worker 返回的已知用量只结算到原付款任务；未知执行保留该任务的整份预留。即使付款任务已经取消，它仍承担此前授权且为其他订阅者继续执行的这一次物理请求。费用不会被转给其他任务，也不会因为取消而被清零。所有成员的结果、收据和结算在同一事务内提交；正文快照只保存一次。

`job.get` 增加 `shared_reads`：成员尝试数、订阅尝试数、待结算/未知尝试数，以及关联的已知请求/字节数。`job.results.items[]` 对共享尝试增加 `shared_read`，包含 `attempt_id`、`payer_job_id`、付款输入位置、成员数、角色和结算状态。

这些 `associated_*` 字段说明一次共享工作与任务的关系，**不得相加当作额外物理用量**。原有 `usage.external_requests/content_bytes`、未知预留与 `budget.charged_*` 仍表示实际归属到本任务的消耗。关联用量未知时返回明确的未知状态，而不是伪报为零请求成功。

## 取消、暂停与发布

`job.control(cancel/pause)` 先推进被操作任务的持久代数并撤销其发布资格。只要同组仍有有效订阅者，就不发送 `fetch.cancel`；付款任务取消也不会取消其他订阅者。最后一个有效订阅者离开时，核心才请求 Worker 协作停止。

取消 RPC 不是发布屏障。Worker 可能已经下载完成或迟到返回；提交时仍逐成员重新检查任务状态、权限、期限、租约和删除代际。只有仍有效的成员能得到收据。已取消/暂停的成员不会因为另一个成员成功而取得自己的任务结果，但同 owner 的正常权限仍决定其对其他已保存资料的访问。

主体撤权或 URL 删除会使相关成员全部失去资格。没有有效订阅者时不写正文。共享成员的收据写入失败会回滚整个正文/索引/收据事务，再由失败路径结算一次物理用量。

## 重启、保留与边界

进程重启后成员关系和付款归属不变。未过期的租约不会重复派发；租约到期仍无可靠回执时，整组标记执行未知，付款任务保留整份预留，订阅者记录关联未知状态。不会自动重发。只有任务原本允许的次数、剩余预算和期限均满足时，才可通过显式 `retry_failed` 发起新的尝试。

任务压缩仍要求原有至少七天的稳定终态资格。压缩一个任务保留永久幂等键和含共享统计的摘要；物理请求记录在其他成员明细仍存在时继续保留，因此付款任务先压缩不会丢失剩余成员的付款归属。最后一个成员明细退休后，已结算组才可回收。活动或未结算成员仍由原有任务/预留条件保护。

本实现没有新增真实网站批准、凭据共享、跨 owner 复用、恢复隔离豁免或付费回退。独立撤销 journal 连续性、广泛长时运行和完整 CACHE-01/B-24 验收仍按原计划推进。合成 Worker、可控时钟和 SQLite 双连接用例分别证明其覆盖的行为，不替代真实公网、任意断电或多节点演练。
