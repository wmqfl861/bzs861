# 普通直接读取的成员取消

本增量在[直接共享读取](DIRECT_SHARED_READS.md)上提供可选的一次性成员句柄，继续推进 `CACHE-01 / FT-032 / B-24`。版本仍为 `0.1.10`，数据库仍为 schema15；未新增持久任务、预算账本或数据库迁移。

## 调用顺序

| 操作 | 参数 | 结果 |
| --- | --- | --- |
| `web.read.prepare` | `{}` | 分配一个当前 owner 专用的 `read_id`；不调用 Worker、不访问来源。 |
| `web.read` | 原读取参数，可选 `read_id` | 使用句柄一次，仍同步返回原读取结果或错误。 |
| `web.read.cancel` | `{"read_id":"…"}` | 取消该成员；必要时通知 Worker 协作停止整次物理读取。 |

例如先调用：

```json
{"operation":"web.read.prepare","params":{}}
```

返回 `read_id`、`scope="process"`、`state="prepared"`、`expires_in_ms=120000`。客户端保存这个 48 位小写十六进制 ID，再从一个连接发起读取：

```json
{"operation":"web.read","params":{"url":"https://example.com/page","freshness":"refresh","read_id":"替换为准备阶段返回的ID"}}
```

读取进行期间，另一个经过同 owner 认证的连接可调用 `web.read.cancel`。CLI 的通用 `call` 入口支持这些操作；MCP 对应 `prepare_read_url`、带可选 `read_id` 的 `read_url`、`cancel_read_url`。适配器只转发核心结果与用量。

没有 `read_id` 的旧调用继续原路径。带句柄的调用只与其他带句柄且完全兼容的调用共享；两种调用不混合。它们各自仍满足原完整 owner、URL、权限/删除/发布捕获、超时、条件身份、缓存 metadata 和 Worker profile 匹配要求。

## 句柄状态与容量

句柄属于创建它的 `WebService` 和 owner。未知、过期、其他 owner 或重启前的句柄统一返回 `E_NOT_FOUND`（404）；格式错误返回 `E_SCHEMA`。其他 owner 不能用控制接口探测句柄状态。

核心在缓存、profile RPC 和网络路径之前原子认领句柄。已经认领的句柄再次读取返回 `E_READ_STATE`（409），不能重新执行或附着到新尝试。认领后参数错误也会消费该句柄。准备阶段取消后，第一次读取消费句柄并返回 `E_CANCELLED`（409），新增用量为已知零；不会派发网络读取。

每个 `WebService` 的准备、活动和保留终态句柄合计最多 **1024**。满额的新准备请求返回 `E_READ_CAPACITY`（429），不驱逐既有条目。准备条目保留 120 秒；实际读取退出后，终态重新保留 120 秒。使用 `steady_clock` 计时，重复取消不延长期限。

**正在运行的读取不因保留时间到期而被清理。** 即使付款成员已经接受取消，它仍可能承担同步物理调用，必须等该读取退出才能开始终态保留期。成员退出后不在句柄表保留快照或共享组对象。

## 单成员取消与整组停止

| 场景 | 成员返回 | 物理尝试与归属 |
| --- | --- | --- |
| 准备阶段或进入网络前取消 | `E_CANCELLED`，已知零新增用量 | 不新派发该成员的读取。已开始的本地 profile RPC 可完成。 |
| 订阅者取消，仍有其他成员 | 立即唤醒等待者，返回 `E_CANCELLED` | 物理请求继续；订阅者增量为零，未结算的关联物理用量为未知。 |
| 付款成员取消，仍有其他成员 | 原同步 `web.read` 等物理调用结束后返回 `E_CANCELLED` | 付款归属保持，其他成员仍可成功；不转移或清零原付款消耗。 |
| 最后活动成员取消或退出 | 该成员不再获得正文 | 先在协调锁内关闭加入，再在锁外最多发起一次协作取消。 |
| 成员已完成交付后取消 | `state="completed"`，`cancel_requested=false` | 不撤回已完成结果，不影响后来的读取。 |

正常取消确认返回 `state="cancelled"`、`cancel_requested=true`。`physical_cancel_requested` 仅表示**本次控制调用首次发起**整组取消 RPC；重复调用为 false。它不是 Worker 已停止的证明，也不表示已发请求或用量被撤销。控制 RPC 等待上限为 2000 ms；回包失败时逻辑取消仍生效，不自动重试。

取消不释放每组 **32 个累计成员**的槽位。仍有活跃成员的兼容组可接纳迟到成员；最后成员退出后已关闭的组不会重新开放。新的读取使用新的物理关联 ID，原组的迟到完成或取消不能关闭新组。**64 个开放共享组**的上限及同线程重入、超限独立执行规则保持。

成员成功交付的认领在窗口的 Store 事务结束后，由同一协调锁与取消决定先后。取消先赢时，该成员没有成功正文；交付先赢时，后来的取消不能改写已经完成的结果。

## 发布、缓存与权限

付款路径在提交正文之前检查仍有活动成员。若最后取消已经赢得这个提交准入点，核心只保留合法的缓存撤销和限制性发布观察，不新提交正文。Worker 忽略取消或取消回包丢失也不能绕过此检查。

提交准入检查与 Store 事务之间不持协调锁，取消仍可能发生在该窗口内。因此取消不承诺回滚已开始或已完成的存储提交；最终成员交付仍受独立取消检查以及原权限、删除、metadata、页面/站点发布屏障约束。取消不能放宽 `no-store`、`noindex` 或其他已验证限制。

`Service` 在读取完成后做最后主体有效性检查。若这一步发现撤权，仍拒绝正文，并保留 `web.read` 已计算出的 `usage` / `shared_read`。这一补充仅作用于直接读取；其他操作原错误合同保持。

## Worker 协议与用量

带句柄的物理读取使用 `fetch.extract_direct`，参数是原普通读取参数加独立 `control_id`；停止入口是 `fetch.cancel_direct`。没有句柄的调用仍使用原 `fetch.extract`。

该控制命名空间与持久批读的 `attempt_id` / `FetchBudget` 分离。它保留普通读取的 60,000 ms 参数上限、输出窗口、下载截断、重定向响应体处理、直接及跳转条件重验证规则，不附加持久预算 grant。旧 Worker 不支持新 RPC 时，该显式控制读取失败；核心不会自动降级重发。

Worker 的活动和保留控制合计最多 **2048**。活动项不按时间清理；完成、失败和取消记录保留 120 秒。保留期内的运行中重复、退休重放或取消前到达的同 ID 不能重新出站。重复取消不刷新既有退休期限。

控制只打断该次读取正在等待的网络子任务，包括主机槽、响应头和正文块等待；父 RPC 与 CPU 提取任务保持自己的生命周期。CPU 提取结束后仍复查取消，不把已经取消的结果作为成功正文交付。来源请求一经派发即累计，实际消费的解压后响应体字节继续累计；取消后的收据保留这些用量。该字节数不是协议头、TLS 或网络栈缓冲总流量。

付款成员承担一次物理增量；订阅成员新增为零，关联物理用量只供追踪同一次执行，不能重复相加。提前退出的订阅者不读取付款线程仍在写入的收据，关联物理值保持 `null / known=false`。RPC 无可靠回包时也保持未知，并在最后成员退出时尝试一次协作取消；取消确认不制造零消耗或允许自动重试。

## 接纳与恢复边界

本批 HTTP 入口新增固定 **1 个取消控制执行槽**。在 Host、Origin、路由、Bearer 认证及 Content-Type 检查通过后，只有不超过 **4096 字节**、通过严格 JSON 检查且仅含 `operation="web.read.cancel"` 与 `params.read_id` 的合法结构才进入该槽；`read_id` 必须为 48 位小写十六进制。重复键、伪操作名字符串、未知字段、错误类型或大小超限的正文按普通请求接纳。分类不访问 Store 或 Worker，进入 Service 后仍完整执行 owner、主体撤权及句柄检查。

普通业务池和控制池各自限额且不能互借容量，没有额外等待队列；`web.read.prepare`、`job.control`、`session.cancel` 继续使用普通业务池。普通池满而控制槽空闲时，符合分类的取消可被接纳；控制槽满时仍返回原 503，即使普通池有空槽。此时取消**尚未被接纳**。客户端必须检查控制响应，不能把发送过取消请求当成取消已成功。

固定槽不提供独立连接额度，既有 **64 个活动连接**上限、请求读取和响应写入各 5 秒的 socket 期限、Worker 原期限保持。连接已满、控制池已满、IO 无法调度或 Service 等待 Store 锁时，仍不保证即时接纳或完成；这不是取消 SLA。两个请求池均在 Service、Store 和 IO 对象销毁前停止并 join。严格分类、启动报告及生命周期详见[HTTP 请求执行与背压](HTTP_EXECUTION.md)。

该协议只在当前进程内有效，没有持久直接读取账本、跨进程取消、跨实例共享或重启后的执行回执。120 秒保留也不提供任意长进程挂起、延迟网络重放或 Worker 重启后的恰好一次保证。客户端断连不是取消，未知执行不能自动重发。

本批控制槽的实际源码、执行输入和结果见[取消接纳验证记录](../validation/http_cancel_admission_20261025/README.md)，不预填尚未结束的测试或 CI 成绩。[上一批成员取消记录](../validation/direct_cancel_20261025/README.md)属于该业务合同的历史证据，不能代替本批 HTTP 接纳验证。原来源/站点、人工 qrels、备份隔离、撤销连续性和历史证据要求保持。跨 direct/durable/map/crawl/search 的兼容共享、长期故障及完整 `CACHE-01 / B-24` 仍待推进；原 **37 partial / 46 not_started / 0 accepted** 不因本增量改变。
