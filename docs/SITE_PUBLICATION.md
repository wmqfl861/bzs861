# 存量网页结果的站点发布上限

本页定义始于0.1.5、在0.1.8沿用并扩展的 **`bzs-site-publication-1`** 部署行为，对应 CRAWL-03 / FT-029、B-23、C-02 的继续实现。页面自己的 `bzs-publication-1` 声明见 [SITE_CRAWLING](SITE_CRAWLING.md)；两类规则共同约束检索输出。当前证据见 [验证说明](../validation/s2_five_stages/README.md)，完整工作包与 S2 均未签收。

## 解决的问题

0.1.4 在新的网页响应到达时执行发布规则，但站点清单后来被收紧时，已存索引和冻结搜索页可能继续返回原摘要；只用 `--sites`、不启用 Worker 的离线启动也没有激活这项限制。0.1.5 把站点发布上限保存在核心数据库中，使新搜索、旧搜索分页和当前回执都能使用持久规则，不需要再次访问网页。

| 当前站点审核 | 已存网页的搜索输出 |
|---|---|
| 审核有效且允许有限再发布 | 仍需满足页面声明、历史限制水位、owner 权限及删除检查 |
| `redistribution_policy=links_only` | 可以保留允许索引的链接；摘要为空、标题使用 URL、不提供正文高亮 |
| 未启用、拒绝、审核过期或不满足既有审核条件 | 相关网页退出新搜索和旧冻结分页 |
| 已登记路径被移除，或明确清空已有站点登记 | 原范围保留为已撤发布的历史 scope，不能通过删除配置恢复旧内容 |

这项约束针对网页的检索发布。owner 已有权限的完整快照、原文范围和证据仍可显式读取；原有删除与权限撤销规则照常拒绝访问。显式导入的资料不因为同 URL 后来抓取了网页，就被网页站点上限错误隐藏。

## 如何激活配置

```bash
searchd --auth /absolute/path/auth.json --state /absolute/path/state --sites /absolute/path/sites.json
```

显式 `--sites FILE` 在核心启动时激活持久发布规则，即使没有 `--worker`。同一文件的精确 SHA-256 身份重复激活是幂等的，正常重启不会生成一个新的限制代际。省略 `--sites` 保留数据库已生效的规则；它不能清空历史上限。

显式空清单的行为取决于已有记录：有历史站点 scope 时撤回那些范围；从未登记过站点时，空清单不会撤回无关的普通网页读取。历史登记仅覆盖明确路径；同一 origin 下从未登记、能够明确判定范围的其他路径，保留原来的显式读取语义。编码分隔符等使路径归属无法安全确定时，对登记 origin 保守收紧。

运行期间到达审核失效时间，下一次相关核心操作会持久化撤发布水位并立即检查输出。它不需要新 HTTP 请求，也不靠文件热重载。修改文件仍需重启以明确激活。自动 map/crawl 的 Worker 继续加载同一个精确清单；已有实例发现持久清单已变更时拒绝按旧配置派发或提交。

底层 C++ 使用 `Store::activate_site_publication` 表示显式部署激活。旧 Store / WebService 不能覆盖其他实例后来激活的清单；已创建的读取实例保留自身代际，晚到的宽松结果不能抬高新上限。新开 Store 后显式激活旧磁盘文件仍视为一次新的部署决定；CAS不判断文件是否过时，已有历史水位继续有效。

## 为什么放宽配置不会复活旧会话

每个历史 origin/path scope 保存当前模式，以及最后收紧索引、摘要的单调水位。新网页快照绑定读取实例的发布代际、读取当时的有效站点模式和完整 URL 身份集合，格式为 `bzs-site-bindings-1`。身份包括逻辑入口、实际最终页和每个中间跳转；crawl 使用核心已确认的逐跳账本补足其单跳 Worker 回执。

搜索结果使用当时快照的不可变绑定。入口后来改指向别处、相同正文在另一条跳转链上出现，都不会改写旧结果所代表的 URL 链。绑定或代际变化会形成新的快照身份；旧快照和证据继续指向原正文。

收紧后再放宽清单，会把释放限制前的旧读取代际封入历史水位，只能允许新的完整读取重新形成合格表示。它不会使低于历史水位的旧摘要或旧冻结页恢复。更窄路径继承已有祖先的历史水位，不能通过添加子路径绕过过去的撤回。失败、截断或旧实例晚到的读取也不能作为恢复依据。仅修改审核备注会改变清单身份，但在禁止期间取得的新正文仍永久携带当时的禁止模式，不能在后来放宽时绕过旧水位。

## 即时输出门控与有界索引清理

核心在 FTS 与非 FTS 搜索候选的 `LIMIT` 和冻结计数形成之前检查站点资格；旧分页同样在事务内检查。受禁止的结果不能挤占候选窗口、继续暴露旧摘要或由分页重新出现。

物理 FTS 清理每次事务最多检查 128 个当前文档，持久游标在后续操作中继续推进。输出资格立即生效，不等待整个历史库扫描完成。因此不能把一次配置激活描述为所有物理索引行已经清空。owner 的 canonical 正文和证据不属于这项物理清理。

站点规则最多保留 4096 个历史 origin/path scope；单个快照最多绑定 24 个 URL，持久清单不超过 1 MiB。超过边界会明确失败，不静默遗忘历史限制。当前[任务明细回收](JOB_RETENTION.md)只处理固定保留期且已结算的终态前沿/请求跳等详情，保留永久身份与计费；scope/删除发布历史和独立撤销要求不清理，不能手工清策略或账本绕过容量。

## schema 7 升级影响

schema 7 在原 schema 6 上添加持久站点状态、scope 水位、快照绑定和冻结行版本，并加入 crawl trap 观察表。继续保留更早 schema 的兼容与隔离拒绝路径。旧版本没有完整保存所有历史跳转信息，不能仅凭现存 `final_url` 重建已经丢失的中间路径。即使schema6没有保存scope明文，已有crawl任务仍能证明曾有受管抓取；此时首次显式空清单同样撤回旧crawl表示。

首次激活有站点历史的配置时，缺少新绑定版本的旧网页冻结行保守退出发布。由旧 crawl 任务证明、但不能证明完整链的旧网页当前快照也会暂时撤发布，直到完整重新读取。旧普通网页读取可在现有可靠元数据允许时供新查询使用；新的冻结结果使用新绑定规则。显式导入行保持自身性质。

所以升级后部分旧搜索会话可能变空，部分旧 crawl 文档需要重新读取才能重新出现在搜索中。这不是正文或证据删除，也不宣称恢复了旧版本没有保存的历史。已有权限撤销、删除、隔离和备份恢复要求仍独立生效。

## 可观察结果与验收边界

快照信息和 `web.read` 返回 `site_publication`，包括版本、当前 `mode`（`allowed` / `links_only` / `withdrawn`）、当前代际和 artifact 代际。`read_many` 的任务回执返回当前版本/模式/代际；crawl 条目及其回执通过当前 `indexed`、`publication` 和其中的 diagnostics 表达限制。`body_read`、`available`、快照身份和私有完整正文按原含义返回，不把“已读取”误写成“可公开发布”。

实际回归覆盖零 HTTP 的 links_only/拒绝/过期/空清单、同源范围变化、旧实例、完整跳转链、冻结表示、物理清理窗口、owner/导入隔离、删除与容量。它们是受控代码和进程验证，不是独立站点法律审核、完整公开集合等效验收或全产品安全签收。已交付到外部的内容无法收回；持久站点水位也不是独立撤销日志，不能据此解除历史备份的隔离。

## 0.1.6 页面响应顺序与 schema8

真实读取派发时捕获持久发布序号；索引和摘要限制分别保存历史代际。较早允许响应晚到时，逻辑URL、最终URL和中间跳转中的较新限制仍封闭其发布资格。即使限制值与正文相同，新的限制观察也会推进水位。删除最终目标也能阻止旧逻辑别名回包写入。限制只作用于对应owner和真实URL，不以搜索去重键扩展策略身份。

后发完整读取可以获得新表示；经过新水位时，同体响应也可能生成新snapshot，旧快照派发身份与元数据保持不变。冻结行不能因后来允许、删除后重读或重定向改道恢复旧摘要。schema7在途条目的未知派发快照使用独立迁移标记，不能视为真实空快照。以上页内水位不是独立撤销日志，也不解除恢复隔离。

完整性检查同样约束没有新版发布字段的兼容回包：显式非成功HTTP状态、206部分正文或无安全限制声明的截断响应不会生成允许发布的新快照。旧Worker未提供HTTP状态的既有兼容路径仍保留；这不等于省略了已报告错误与截断检查。
