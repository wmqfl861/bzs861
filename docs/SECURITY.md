# 安全边界（0.1.4 S2 crawl development candidate）

本候选版用于本机、单用户阶段，尚未完成全产品独立安全发布审核。以下是必须维持的边界；修复是否通过具体测试，以 [本轮报告](../validation/s2_crawl/test_report.json) 和 [范围受限的交叉复核](../validation/s2_crawl/independent_review.json) 为准。原 Claude S1 输入的审查继续保存在 [历史记录](handoff/CLAUDE_S1_REVIEW_20261018.md)。

## 通道与权限

| 通道 | 当前边界 |
|---|---|
| Agent → MCP | 优先 stdio；HTTP 只监听回环、每客户端 Bearer token，无鉴权 HTTP 被拒绝 |
| MCP / CLI → searchd | 回环 HTTP、Bearer token、Host/Origin 校验、请求/连接上限；共用核心授权和业务 |
| searchd → worker | 回环 HTTP、独立 worker token、大小与时间限制；worker 不写数据库，不能仅凭核心声称已检查放行 |
| worker → 网页/来源 | 检查目标并绑定实际连接，逐跳重查；来源执行还须满足审核和启用条件 |

令牌不进入样例、网页上下文或公开日志。认证文件按平台权限规则保护；Windows ACL 与完整平台发布仍需验收。本机 MCP HTTP 不代表 S5 的 TLS、按客户端限流、审计和远程隔离已完成。

## 出站与凭据

- 正常抓取只接受 HTTP(S) 公网目标，拒绝 userinfo、歧义数字主机、回环、内网、链路本地、元数据及其他不可公开路由地址。
- DNS 结果必须绑定实际连接；重定向、meta refresh 和跳转页再次检查。来源返回的 URL 不自动获得信任。
- 跨来源重定向不转发 Authorization、API-Key 等凭据。账号/API 凭据不能泄漏给页面指定的新 origin。
- 下载、解压后字节、正文、超时、重定向、并发和预算分别受限；不允许无限重试或付费回退。
- 生产拒绝 `proxy`、`proxy_remote_dns` 和非空 `allow_cidrs`。代理重新解析与任意网段放行不满足连接绑定保证，网络失败如实报告。
- 假网站回环映射只由受控 fixture 提供，不开放为 CLI、HTTP、MCP 或普通配置的内网开关。

## 来源审核与准入

13 个随包适配器是未核验候选，默认 `enabled=false`、不作为默认来源。正常核心操作和 worker RPC 都必须拒绝未审核、禁用或审核过期的来源；调用方选择 ID 不能越过准入。

S0 是显式候选探测入口，测可达性、阻断、解析与延迟；它不自动启用来源，`usable` 也不表示条款、免费条件、自动访问、缓存/再发布已获审核。可用性和审核记录分别保存，审核需有证据、日期和到期语义。

调度保留间隔、配额、冷却和 `Retry-After`；遇验证码/封禁不破解、不轮换身份绕过。索引族独立性不明时保守控制贡献，不能以多个适配器增加独立索引票数。

## 自动发现与爬取准入

`map.submit` 和 `crawl.submit` 使用独立且默认空的 `sites.json`。每个 origin 的审核身份、有效日期、路径范围与可信限额在核心和 Worker 分别检查，精确文件哈希必须一致；搜索来源审核不能授权任意结果站点。robots 规则提供额外请求约束，不授予访问授权。

自动发现的每个内容请求使用固定 BzsBot 身份，并在实际发送前核验有效 robots 记录。无法确认允许、规则过期、解析损坏、限流或不可达时不派发内容。robots 元数据获取本身也消耗预算；同源跳转逐跳交回核心，跨源 robots 跳转拒绝。URI 比较和实际发送使用同一 ASCII path/query 表示，避免客户端再次规范化改变规则判断对象。

核心持久控制唯一队列、请求预留、站点配额、冷却、租约和恢复。未知请求结果继续保守计费；暂停、取消、授权或删除变化后旧执行不能回写候选。重定向当前目标和历史原文档身份也参与删除复核，不能只检查初始 URL 的 tombstone。

crawl 沿用该单跳通道增加正文前沿与页预留，不能通过循环调用普通读取绕过 robots。map/crawl 共用持久轮转次序和同源状态；每个逻辑正文资源、HTTP 跳和边分别记录，不把失败或未知执行伪装为未发生。正文、索引、收据、边及用量提交时重新检查租约、权限、期限和删除身份。重定向正文还保留实际内容 URL 的表示绑定，既有 URL 别名与旧搜索会话不能逃避最新发布限制。

发现文档和 URL 集合有硬容量上限，查询变体和深度有界，XML 禁止 DTD、自定义实体和外部资源展开。HTML/feed/urlset 产生候选，不会自动生成正文快照或公开索引。候选中的恶意或越界 URL 被逐项过滤并记录，不能污染有效候选；后续请求仍须独立准入。详细策略和限制见 [SITE_DISCOVERY](SITE_DISCOVERY.md)。

上一段描述 map 的候选语义；crawl 单独提交后才扩张正文前沿。它还限制正文页和边数量，拒绝超范围的重定向、未知调用方字段以及预算类型转换。MCP 新 crawl 工具在 SDK 处理前拒绝布尔/字符串/显式 null 预算，避免它们激活其他默认值。具体合同见 [SITE_CRAWLING](SITE_CRAWLING.md)。

## 配置与执行

保留三类原生 `contract.validate`，时钟和部署限额由服务端提供。`validated=true, applied=false` 只证明固定合同和运行时约束通过，不证明审核元数据真实，也不注册来源、读凭据、调用模型或授予出站权限。调用方不能修改审核时钟或放大预算。

模型未来的内网授权独立于网页通道，不能扩展为页面/Agent 的访问权限。见 [CONFIGURATION](CONFIGURATION.md)。

## 内容与发布

网页正文、搜索摘要是不可信外部数据。隐藏元素过滤、提取器和 `content_trust` 只是辅助，可见正文也可能有恶意指令；网页不能修改来源、凭据、部署策略和权限。

摘要、已读正文、原文证据分别标注。证据只保证快照/字节位置，不自动评价事实或语义支持。权限覆盖正文、片段、证据、分页、统计和缓存的新发布入口；已交付到外部的数据无法撤回。

页面发布策略 `bzs-publication-1` 与 robots 请求许可独立。适用的 noindex 立即撤索引和冻结结果，nosnippet/data-nosnippet 限制新旧搜索摘要及安全标题。摘要从独立允许的文本生成，不用 canonical 正文回填被禁止片段，也不把重提取摘要的偏移当作原文字节证据。站点 `links_only` 是额外上限，不能通过普通网页或批量刷新清除。

正文读取路径（crawl 的 page、普通 web.read 和 read_many）的实际响应携带禁止声明，但正文解析失败、被截断或不能保留时，独立的限制观察只能收紧已有发布；它不产生正文收据或任何访问授权。该更新同样校验响应身份、当前租约和删除屏障；失败响应的允许声明不能复活已撤下内容。map 的独立发现元数据不执行该正文发布更新。逻辑存储配额与实际磁盘故障分别报告，不将无法提交的存储操作宣称成功。

保留 owner 隔离。按文档 tombstone 可以减少无关失效，但不削弱真实撤权和删除对象的发布屏障；在途任务不得复活内容。隔离备份不能直接启动服务，无法证明最新撤销水位时继续隔离。单用户排序不免除这些性质。
