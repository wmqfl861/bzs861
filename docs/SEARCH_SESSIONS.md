# 持久搜索会话与断线重取

本增量给现有本地冻结搜索补上事件接口，并增加 `web.search.start` 联网会话。C++ 核心保存队列、来源尝试、结果版本、游标和事件；Python Worker 只执行已批准来源的一次请求，MCP 只映射核心接口。原 `web.search` 保持同步兼容入口；需要冻结分页、重连或取消时使用新会话入口。

## 开始、观察与分页

```json
{"operation":"web.search.start","params":{"query":"example","sources":["approved_source"],"idempotency_key":"search-001","limit":20,"per_source":10,"timeout_ms":8000,"deadline_ms":120000}}
```

来源 ID 必须来自当前已批准的配置。默认生产配置仍禁用所有来源。单会话最多 20 个来源，每源最多 30 条候选，最终版本最多 50 条。`timeout_ms` 为每次来源请求的预算（1–30 秒）；`deadline_ms` 为整个排队和执行期限（1–600 秒），过期后不再接受发布。RPC 清理或已在途请求可以晚于期限返回，核心会拒收过期结果。

开始响应包含 `session_id`、状态和最新 `result_set_version`（尚无完成结果时为空）。请求的 `deadline_ms` 是相对时长，状态响应同名字段是绝对截止时间。同一个 owner 使用同一幂等键和同一规范化输入/来源配置，得到原会话；不同参数或配置产生 `E_IDEMPOTENCY_CONFLICT`。通过当前来源准入后，过期旧键返回 `E_SESSION_EXPIRED`，不会重发来源请求；当前审核或配置错误也可能先被拒绝。新查询使用新键。

核心每次派发一个来源；同类会话按持久队列序号轮转，与已有导入、批读、map/crawl 各保留一个后台循环机会。每个完整来源响应提交后，用现有 C++ `fuse` 重新合并已完成来源，创建新的不可变结果版本。新版本可以重新排序，已有版本及其分页顺序保持不变。同索引族仍只计一份 RRF 权重；没有 Python 排序副本。

查询 `session.get` 获取状态。分页请求必须携带选定的联网 `result_set_version`：

```json
{"operation":"search.page","params":{"session_id":"SESSION_ID","result_set_version":"VERSION_ID","page_size":20}}
```

后续请求传回 `next_cursor`。游标绑定 owner、会话、结果版本和下一位置；不能用于其他版本。相同游标可以重复拉取，由客户端按结果版本及位置去重。本地搜索的版本仍等于会话 ID，旧的本地 `search.page` 调用继续可用。

每一页都重查 owner、授权代际、删除、已知页面发布限制和持久站点上限。形成版本时已经生效的删除、noindex/nosnippet 同样固定到版本，后来完整允许读取、显式重导入或重定向变化不能恢复该旧版本；新合格查询/版本可以反映新表示。来源派发复核当前配置身份，分页检查冻结来源合同有效期，超期后拒绝提供会话。冻结合同检查不等于独立来源撤销日志。事件和冻结数据是受控搜索内容，不能作为指令或可信正文；联网结果的 `body_read` 仍为 false。

## 事件重放与慢客户端

```json
{"operation":"session.events","params":{"session_id":"SESSION_ID","after_event_id":0,"limit":20}}
```

`event_id` 是会话内持久、严格递增整数。处理完成后保存 `next_event_id`；重连时继续传入，按 `(session_id,event_id)` 去重。一次最多返回 32 个事件，`has_more` 表示还有待取事件。没有新事件时返回空数组、核心时间和建议轮询间隔；心跳不写入日志，不因慢客户端建立无界内存队列。

事件只保存状态和版本 ID，不保存旧标题、摘要、URL、查询正文或历史候选数量。内容必须经分页接口重新鉴权。因此重放旧事件不会重发已经撤回的搜索内容。

每会话最多保留 64 个事件，事件保留 10 分钟；超过事件保留窗口返回 `E_EVENT_HISTORY_EXPIRED`。此时先调用 `session.get`，选择仍可用的冻结版本重新分页，或者重新查询。会话和完整结果版本最多保留 1 小时；超过会话期限返回 `E_SESSION_EXPIRED`。

## 取消和不确定请求

`session.cancel` 取消尚未派发的来源，并递增执行代际，封住在途回包。已经完成的版本保持到会话过期。重复取消不新增事件；已完成会话返回原完成结果。

当前 Worker 的来源搜索 RPC 没有中断接口，所以已发出的请求可能在其有限超时内继续完成；该结果不能在取消后发布。`dispatched_source_attempts` 是核心已预留的来源尝试数，`unknown_source_attempts` 是无法证明结果的尝试数，二者不是精确实际 HTTP 成功数。租约过期或回包丢失后保留未知计费，不自动重发该来源，继续未派发尾部。现有来源共享预算和冷却保持独立约束。

## 容量与持久身份

未过期的本地/联网完整会话共用每 owner 64 个、部署256个的上限。每个联网会话的候选来源载荷、冻结行、请求与审核记录合计最多 4 MiB；达到上限返回明确背压并保留已有版本。事件有独立数量上限。所有写入和游标提交使用 SQLite 事务。

过期完整载荷可以回收，幂等身份与累计尝试摘要继续保存：每 owner 最多 10,000 条、部署最多 100,000 条，到顶返回 `E_SESSION_BACKPRESSURE`。这提供有界保留，不能描述成无限容量。队列、已知/未知计费和删除/发布水位不因清理会话载荷而倒退。

## MCP

结果融合保留参与标题/摘要表示的真实候选 URL，包括同一来源初次融合和跨来源再次融合中的 HTTP/HTTPS、查询参数变体。分页重新核对这些真实 URL 的冻结与当前重定向链、删除及发布限制；搜索去重键不作为策略身份。每行最多保留24个可核对URL和24条历史表示记录，无法完整绑定时禁止该行发布，旧crawl兼容标记不能清除已经捕获的限制。同一来源的重复命中继续使用最优正rank，冻结过程保持既有核心RRF得分和顺序。

本地与联网会话共同受容量上限约束；过期本地结果和游标随维护回收，直接开始联网会话即可恢复空间。MCP在SDK转换前检查原始JSON类型和未知字段，拒绝将字符串来源列表或布尔预算转换为默认来源或新的额度。

新增 `start_web_search`、`get_search_session`、`search_session_events`、`search_session_page`、`cancel_search_session`。开始与取消的副作用标记明确；查询/分页/重放不请求来源。参数由核心验证，适配器不把零预算改成更大的默认值。

该增量是 SESSION-01/02 的部分实现，提供拉取式等效传输。真实来源长期运行、物理断电、多节点共享部署和完整 161 项验收仍需单独取证。会话事件日志不属于独立撤销日志，不能据此解除备份隔离。
