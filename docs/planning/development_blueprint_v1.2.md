## 2. 架构

Agent 经 Python MCP 适配层调用回环 HTTP 上的 C++ searchd；核心以另一条独立令牌的回环 HTTP 调用 Python worker。核心保留合同、授权、预算、审核与准入、调度、聚合、会话、缓存、快照、索引、证据和任务。worker 负责网络/解析并独立复核来源和连接，MCP 只映射工具。后续远程入口在 S5 的安全门槛通过后开放。

| 组件 | 负责 | 不负责 |
|---|---|---|
| searchd | 原生合同、权限、来源审核/准入、预算/冷却、缓存、持久数据、聚合排序与证据 | 直接外网获取；保留受限本地 HTML 导入路径 |
| bzs-worker | 网络/解析；独立执行来源合同准入和连接层检查 | 写数据库；扩大核心策略或凭调用方绕过审核 |
| bzs-mcp | 把 MCP 工具映射到核心操作；输出精简结果；标注网页内容为不可信数据 | 任何业务规则 |

进程间只用回环 TCP 上的 HTTP JSON，Windows 下同样适用。启动、停止由跨平台的 Python 启动器 `bzs` 管理。

### S1 完成标准

1. `web_search`：至少 2 个经过有效审核、显式启用并经 S0 真实实测可用的来源，含至少 1 个通用网页源；合并去重、每源状态和单源失败隔离通过。假网站和候选 usable 不能代替审核或真实通用网页证据。

5. 当前主分支与 S1 增量缺陷合并修复，保留原生合同和历史回归；本轮实际自动化与 ASan/UBSan 覆盖有源码/命令/日志绑定。问题对应 `../handoff/CLAUDE_S1_REVIEW_20261018.md`，不能用原包 B1–B7 标签替代本轮核验。
6. `bzs start` 与 stdio MCP 配置可复现启动；本机 HTTP 必须鉴权。
7. 原三类 C++ 配置合同和纯校验 API/CLI 保留，调用方不能改时钟/硬上限；正常来源在核心与 worker 双重准入。
8. schema 3 对两种历史 schema 2 的迁移通过，快照/证据/删除/隔离性质保留；旧备份仍不直接恢复为服务。
9. 生产代理、远程 DNS/CIDR 放宽与无鉴权 HTTP 拒绝；新跨来源凭据、出站与解析边界回归通过。当前 S0/S1 是否完成以实际状态和完整证据判断。

## 6. 替换机制与必须保留的语义

- worker 使用成熟解析库；系统级沙箱、大小/时间限制和浏览器出口仍需独立验收。
- 单用户阶段保留 owner 隔离与发布前权限复核。按文档删除减少无关失效，但删除对象和真实撤权仍被阻断；独立撤销日志与隔离恢复由 S2 BACKUP-00 承接，未知水位保持隔离，S9 补长期演练。
- 可以用 MCP 通知传递进度；SESSION-02 的断线重取、事件/结果去重、取消、过期提示和背压需等效实现。仅有通知不算完成 B-14。
- sqlite-vec 可替换独立向量引擎；仍需模型/维度身份、权限、原子可见性、崩溃恢复和重建验收，不能因同库取消这些性质。
- 161 项验收继续作为验收要求，按适用切片执行。机器映射区分原要求、替换机制、触发门槛、执行状态与证据，完整工作包签收单独记录。
- 原生配置合同已在 0.0.2 交付，不能因模型执行移到 S4 删除；S0 的候选工具不越过正常来源审核。

## 7. Windows 可移植规则（从 S1 起执行）

1. 操作系统相关代码只放在 `src/platform/`，业务代码不直接调用 POSIX/Win32 接口。
2. C++ 依赖必须能通过 vcpkg 在 Windows 获得；Python 依赖必须有 Windows wheel。
3. 进程间只用回环 TCP；不用 Unix socket、`fork`、信号语义。
4. 进程管理放在 Python 启动器 `bzs` 中（`subprocess` 跨平台）。
5. 路径用 `std::filesystem` / `pathlib`，全程 UTF-8（MSVC 用 `/utf-8`）。
6. 保留已有 Windows 核心、原生合同和 HTTP/CLI 测试与固定依赖，命令失败阻止通过；本轮成绩以对应提交 Actions 为准，安装包在 S9 交付。

## 8. 质量评测

- `tests/golden/queries.json`：原 40 条中英文查询的 ID、文字和既有分类保留，覆盖精确符号、中文技术、导航、学术、代码、新闻、常识七类；常识按 zh/en 分开存储，holdout 另有保留类别。新增 20 development / 15 regression / 5 holdout 划分，由 `tests/golden/manifest.json` 冻结输入、分类、顺序和留出元数据。当前没有人工相关性标签。
- S0：probe 显式指定 `--include-candidates --only <来源 ID...>`，可用 `--sources` 选择清单路径。按 capability/category 分层确定性选题，默认不使用 h* 留出、不向无关能力回退。schema 2 产物绑定输入、选项、解析器与依赖，保存原始证据和至多 10 条完整解析结果；离线 replay 不补抓网络样本。可用性与解析一致性不自动批准来源。
- `quota_scope=this_probe_run` 只覆盖本次探测，未并入 searchd 部署账本或跨次日配额。恢复同次运行需要原身份一致，completed/uncertain 请求不自动重发；不能用重跑掩盖未知执行结果。云端有限样本不能写成用户机器实测验收。
- S2：对黄金查询的前 10 条结果做人工相关性标注，计算 nDCG@10、MRR 和各来源独有贡献；之后每次改排序都对比基线。这一 QA-02 / FT-042 工作仍未完成。FT-008 的黄金/回放底座与 C-14 的部分冻结产物不替代人工标签、环境/语料哈希、预先冻结阈值和完整留出评测，未知门槛保持未通过。
