## 1. 审核方式与状态

用户要求独立子Agent审核。当前会话没有可调用的子Agent执行器；插件能力检索未找到已连接可执行通道，本地也没有可用的Agent CLI，历史记录没有实际可调用的配置。因此没有发送文件给任何独立模型，也不存在可引用的“子Agent原始意见”。

本报告由原作者在当前会话中进行文档自审、基线反例复现、官方边界核对和可执行文档合同检查后形成。**不是独立评审，不作为独立发布批准。** 16项为自审发现，14项采纳，2项部分采纳；“已修订”仅指文档。所有83个产品工作包未开始，161项产品验收未执行。

审核输入哈希见`input_manifest.json`。上传的蓝图、规格、工作簿与原ZIP对应文件逐字节一致：True。未覆盖：产品源码、真实搜索源批准、浏览器/爬虫运行、真实用户模型、平台安装和性能测试。

## 2. 结论

保留独立自研、免费非模型来源、用户配置模型、C++核心和全部产品范围。不建议推倒重来，也不建议因计划过大删去用户已经确认的能力。主要修订为前置依赖、实际可执行合同、索引/恢复一致性、运行资源控制和可验证审查。

设计可以继续推进离线骨架与fixture；关键合同冻结和相关发布仍须真实独立review，以及对应阶段的软件验收。没有真实通用web来源时，可以验证技术流程，但不能签署“免费通用网页搜索已可用”。

## 4. 两项部分采纳的理由

**RV-07：保留基础融合方案，修正身份合同。** 不把未知索引全部并为一个unknown桶，也不把它们都宣称为独立证据。按已审核逻辑服务给候选贡献分组，已知同族合并；检索贡献和证据独立性分开。没有证据支持废除RRF或停掉所有未知索引来源。

**RV-08：保留轻量索引候选，但收紧并发。** 原计划没有足够的读写并发合同。先使用应用级读写锁、单writer、离线代际构建和原子发布；不直接升级为重型向量数据库。上游README明确区分可并行调用与不可同时查询/写入的API，因此“支持多线程”不能当作混合读写正确性的证明。正式C++适配还要固定版本和压力验证。
官方依据：`https://github.com/nmslib/hnswlib`

## 5. 已复现的4个基线合同缺口

| 样例 | v1.0实际行为 | 修订后的要求 |
|---|---|---|
| 完全不配置模型 | Schema拒绝null默认和空profiles | 合法启动基础功能；模型能力单独禁用 |
| 角色级max_concurrency | Schema拒绝覆盖字段 | 能独立设置并在effective_config中体现 |
| 来源审核时间not-a-date | 字符串字段接受 | 格式校验拒绝，并再做审核有效期检查 |
| host字段配after | 结构层接受 | 增加可执行语义/结构兼容检查 |

第四项在旧说明中已明确留给运行时，所以不能称为已实现产品的安全漏洞；问题是资料包当时没有可以执行的语义校验向量。复现记录见`../validation/baseline_reproduction.json`。
