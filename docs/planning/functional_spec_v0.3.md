## 1. 已确认的硬约束

独立开发业务能力；不安装、部署或调用 SearXNG、Scrapling、Firecrawl、Exa 作为执行后端。参考公开功能和协议，不声称掌握专有算法或获得其索引。允许使用合适许可的基础网络库、浏览器、解析器、存储库与模型推理组件。

直接接入经审核的免费底层搜索入口。禁止付费搜索/抓取 API、收费云浏览器、商业代理、收费验证码代答、收费非模型 OCR 产品和试用额度依赖。公共来源可有合理调用上限；达到上限就暂停或返回部分结果，不自动充值。

用户提供的模型配置是明确例外：允许本地或远程文本、嵌入、重排、视觉与转写模型。模型费用不属于上述禁止范围。模型产品附带的托管搜索、抓取和浏览器不是模型调用，不自动获得豁免。模型只连接预先批准的 profile；不把端点密钥嵌入网页或文档。

C++ 核心、Linux 优先、Windows 为目标平台。前端和必要基础组件不强制全部用 C++。不套用其他通用 Agent 项目的主—子—孙组织结构。团队人数、机器配置、正式名称尚未确定，设计使用可调整基线，不编造部署规模。

## 3. 核心语义与不可破坏的约束

### 3.1 搜索源身份
`provider → index_family/dataset → capability → endpoint → adapter`。
底层索引未知时用 unknown，不凭品牌或重复率猜测。来源去重与结果去重分开；同源多个实现共享适用的配额。保留 discovery_source、publisher、原始URL、最终URL及合并依据。首期上线数量是实施批次，不代表来源并集清单只收录该数量。

### 3.2 查询、硬条件与精确模式
统一 AST 是执行合同。结构化条件和查询文本同时存在时必须按约定合并且检测冲突，不由模型静默选择其一。区分 hard filters 与 soft preferences。filter 能力分 native/emulated/unsupported；执行位置不是结果真实性保证。

所有条件核验采用 true/false/unknown 三值语义：否定 unknown 仍是 unknown；AND 有 false 即 false，全部 true 才 true；OR 有 true 即 true，全部 false 才 false。strict 模式主结果仅放 true，unknown 单独列出；exploratory 可以显示 unknown 但不标已满足。

正文中的负面条件必须定义核验字段与覆盖范围。未读、截断、乱码或解析失败不能因“没看到排除词”就证明不存在。时间必须说明 published/updated/discovered/fetched，未知时间不填当前时间。硬条件不可为填满结果而放宽。

字面模式保留 C++、C#、函数名、版本、错误码。中文/大小写/简繁变体用于索引，不覆盖原文；精确字符匹配在原始提取字段复核。正则限安全引擎/复杂度；用户查询不直拼 SQL、FTS 或 shell。

### 3.3 搜索会话
SearchSession 保存查询、来源执行计划、ResultSet版本、已见集合、上游分页位置、权限版本与TTL。流式预览允许明确更新；冻结结果分页只对一个物化排名版本工作。晚到结果/新排序形成新版本，不改旧页。

权限撤销、删除或保留期到期优先于快照稳定性；受影响游标失效并要求重新生成，不维持含敏感数据的旧视图。SSE事件包含单调序号和重放保留期；事件过期不得假装续传完整。计数标记候选/结果集/本地索引、exact/estimated/unknown，不显示伪全网总数。

### 3.4 阅读、原文、模型与证据
HTTP成功≠正文成功；正文成功≠事实正确；引文存在≠支持结论。搜索摘要标为search_snippet，模型摘要标为generated_summary，不冒充已读取原文。

不可变 `canonical_text` 使用 UTF-8，证据定位为 `[start_byte,end_byte)`，边界必须是完整字符。页码、代码行、图片区域、音视频毫秒时间段是附加定位。新解析器/新分块产生新版本；不修改旧引用。片段摘录必须可精确切回对应文本；省略或截断显式记录。

原生文字、OCR、ASR、字幕、模型画面描述分别标注。模型可以建议，但不能放宽权限、抓取范围、调用预算和网络白名单。只保存必要的执行记录与简明决策摘要，不要求模型私有思维链。

### 3.5 索引生效与删除
状态至少区分 discovered/fetched/parsed/index_pending/searchable/failed/deleted。基础增删改、权限失效和索引可见性是首个完整版本要求，不再留到规模化阶段。语义索引可滞后但须返回水位与降级状态；关键词索引成功不冒充向量已完成。

删除/撤权先同步阻断结果、片段、统计、模型上下文、导出和历史游标，再清理派生缓存/向量/内容。备份恢复必须重放最新删除日志。不要只从界面隐藏而保留其他访问入口。

### 3.6 费用、范围与网络
免费审核和健康检查是不同状态。凭据存在不代表来源已获准。搜不到、读取失败、模型不可用，都不能触发收费非模型服务。网页出站、用户模型出站、授权本地文件导入为独立通道；开放模型内网地址不意味着网页也可访问内网。

read不自动跟链；batch仅处理指定列表；crawl才有递归范围。模型和站点脚本都不能扩张scope。截图/滚动等是读取动作，不开放下单、发帖、修改账户、发送消息等副作用行为。

### 3.7 公开发布与私有收藏
公开搜索索引执行本工具声明的robots、noindex、nosnippet等策略，记录适用对象；不要把Google特定行为当作所有爬虫的标准。[S11][S12] 私有授权资料保存另行定义范围，不能用“本地缓存”规避网站访问或内容使用条件。

引用、索引、显示摘要、转写和再分发具有不同权限；图片可见不代表有再发布许可。保留期、no-store、站点政策与用户删除共同作用；不声称一个HTTP指令决定所有法律授权。

## 6. 模型能力目录

默认文本模型可同时承担planner/extractor/verifier/writer。embedder、reranker、vision、asr为明确能力：能力兼容时可复用端点，不兼容则需要用户配置，不拿聊天接口假装向量或转写。

协议适配层优先覆盖OpenAI Chat Completions/Responses和Claude Messages；Gemini等其他协议纳入同一适配机制，实施时按官方协议固定合同并测试，不能仅因为地址长得相似就宣称兼容。[S16][S17] 模型品名、端点、头部、凭据引用、思考配置、上下文、超时、重试、流式和结构输出能力均可配置。供应商原生工具默认不在许可范围。

输入中每项材料绑定内容版本与出站权限。模型调用有次数/输入/输出/总时间边界；实际token或隐藏推理量不可见时记录unknown，不能声称精确硬token预算已经保证。模型返回字段先校验Schema和引用，再进入发布流程。

M0–M8的依赖图、预估工量、并行职责和退出门禁见《开发蓝图与实施计划 v1.1》。R0.1完成M0–M4；R0.2增加M5；R0.3增加M6；R1.0完成M7–M8与全部适用回归。

所有已列功能都需要实现与验收；“缺少用户某项模型配置时正确报告能力缺失”是降级行为，不等于实现了该模型增强功能。对应增强路径最终应使用经授权的测试profile通过验收后才能宣告支持。外部来源因条款或访问限制不能审核通过时保留禁用与原因，而不是伪造可用。

公开图片反向搜索、某个私人App连接器或某个媒体平台的可用范围，取决于获准入口和可读资产。系统必须实现通用能力与至少受控测试环境的端到端路径；不能把无法保证的全互联网覆盖列成已完成。

## 10. v0.3合同澄清

### 10.2 配置三层验证
第一层：JSON结构与字段类型，明确启用日期/URI的format验证；第二层：规范化和语义校验，包括profile引用、字段/操作符、AST复杂度、截止时间、审核到期、role capability；第三层：执行时真实授权、出站策略、端点能力、凭据及预算。设计包的Python参考校验器仅覆盖前两层选定合同，不替代C++运行时和网络安全实现。

允许`default_text_profile=null, profiles={}, roles={}`，核心搜索/读取/爬虫可在不配置模型时运行。文本角色缺省继承默认配置；显式null禁用；专门嵌入/视觉/转写能力缺省禁用。覆盖字段包含reasoning、timeout、max_concurrency、max_output_tokens、retry_limit；部署上限不可被角色/任务覆盖突破。effective_config由程序生成并保存，不能把Schema的default注解当自动赋值。[S22]

`query`是唯一查询主体，可为字符串或AST；hard_filters始终作为附加AND条件。禁止不兼容的field/operator/value/match组合。先做请求体/AST深度节点限制，再进入递归Schema验证；错误日期、URI协议和引用在实际调用来源前拒绝。

### 10.3 robots准入与来源可行性
robots决策先于递归页面请求。请求自身经过出站/限流/预算管控；按RFC9309区分成功、重定向、不可用与不可达，缓存和解析大小按锁定策略执行。服务器/网络不可达且无适用规则缓存时不放行；429采用更保守的限流退避。[S12] 授权交互读取与自动爬虫使用明确模式，不能通过伪装为单页读取规避爬虫策略。

web Alpha必须有至少一个真实审核的通用web来源；论文/馆藏等领域源不能替代。实际源清单和观察窗口是G0输入，未验证者保持disabled。全量候选清点不等于免费性/可访问性已证明。

### 10.4 向量并发与版本可见性
同一可变HNSW实例以应用级读写锁保守保护：只读查询可并发；增删改、容量变化、保存、加载必须独占，并由单writer串行提交。上游API明确不保证add与query并行安全，因此不能从“支持多线程”推导出混合读写安全。[S09] 若未来改为immutable generation+delta，另做ADR及资源/恢复回归，不在首版默认引入两套路径。

离线重建写入新实例，校验模型空间/维度/水位/文件校验和后原子发布，旧实例等引用归零回收。每次查询绑定generation；跨代文档以当前可发布Extraction过滤，历史查询显式指定。保存需绑定ef等未必由库完整持久化的配置，k不足时返回实际数量或partial。索引可重建；不能把模型向量文件当权威内容库。

### 10.5 存储容量与恢复屏障
对临时抓取、原始blob、正文/快照、索引、事件、导出和备份分别配置预算；并发派发预留，下载中校验真实增长。达到高水位暂停低优先级采集，低水位才恢复。GC必须尊重活动任务和证据pin，不能为释放空间删除仍承诺可用的快照。磁盘满、GC和提交竞争有独立故障fixture。

数据库一致备份使用Online Backup API或经验证的停写流程，不直接复制正在WAL写入的主文件。[S23] blob清单按已提交引用冻结并验证。撤销journal不能仅存放在被回滚快照中；须独立保护其最新水位。恢复后默认隔离，只有校验撤销连续性、重放删除/授权、重建派生索引后才对外发布。缺失最新日志则保持隔离，不能把恢复成功冒充安全恢复。RPO/RTO在目标机器实测后冻结，不在本次虚构数值。对外部已送达的文件或模型请求不承诺撤回。

### 10.6 订阅提交与失败
以(subscription_id, query_version, source_id)保存成功checkpoint、扫描区间、覆盖不足和seen集合；使用明确重叠窗口，不能仅按发布时间高水位忽略晚收录/更正。单源失败只阻止其checkpoint前进，其他源可发布partial结果。扫描结果事务提交后写outbox；通知event_id稳定，重发不创建新逻辑事件。接收方无幂等支持时不承诺外部消息恰好一次。

### 10.7 质量门禁和审查独立性
G0记录支持平台/组件版本、目标机器、固定语料hash、测试命令和拟验收方法；M2测基础指标；M3前冻结阈值、留出集和负责人。缺环境、阈值或有效报告时，性能/语义门禁保持blocked；不允许测试后临时降低阈值。安全和确定性合同只对已覆盖样本声明通过，不夸大为绝对安全。

独立review须有实际执行器或独立人员、不同执行上下文、review_run_id、reviewer标识、输入哈希、原始结论和逐项裁决。单纯更换提示词/脚本角色不是独立Agent。`document_revision_applied`、`implementation_verified`、`independently_reviewed`是三个状态，本轮仅完成第一类与文档层检查，后两类未完成。可先开展离线fixture/骨架工作，不得虚报独立发布门禁通过。
