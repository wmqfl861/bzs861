# 本地搜索的并发边界

本地 `search` 与 `search.once` 先在 Store 锁和一个短事务内选取有界候选，保存文档 ID、不可变快照 ID、删除代际、发布水位及原排序分值。随后逐篇复制正文，关闭读取语句并释放 Store 锁，再执行精确匹配和评分。不会一次复制全部候选正文：候选上限仍为 2,000，单次匹配只保留一篇正文及其字段副本。

匹配和非 FTS 评分共享本次调用的惰性 ASCII 转换；一个实际访问字段最多转换一次。词 FTS 仍用原 BM25 分值；其他路径保留原正叶评分、title/body 权重及上限、原稳定排序。纯 NOT 匹配的评分仍为 0。此优化不改变词边界、短语、Unicode 字面量或查询字段语义。

返回或创建冻结会话前，再在一个事务内检查主体撤权和 epoch、文档归属、删除代际、快照是否仍在、当前及捕获表示的页/站点发布约束。匹配期间先收紧、后放宽的 `noindex` / `nosnippet` 仍约束旧候选；原始、最终和中间跳转身份均参与历史检查。当前允许状态不能使受过限制的旧候选重新公开。

并发更新保留的旧快照可以按其原内容返回；删除、删除后重新导入、旧快照裁剪或新的索引禁令会剔除对应候选，并将响应标记为 `partial`。不自动重跑查询，也不把后来导入的新快照加入已选定的候选集合。冻结会话在最终提交时重新检查活动容量，因此两个同时开始的搜索不能占用同一个最后名额。`search.once` 继续不分配持久会话、游标、事件或身份收据。

这项修改释放了精确匹配、评分和排序阶段的 Store 锁。SQLite 候选选择、单篇正文复制、最终可见性投影及摘要生成仍在其必要的锁保护下；不声称整个搜索过程无锁，也不以本地合成数据推导生产延迟或吞吐保证。搜索来源的发布政策约束联网来源结果；它不会自动撤销独立导入的本地文档。站点和网页的发布政策继续约束本地保存的网页表示。

正式回归位于 `tests/unit.cpp`，使用只供友元测试访问器设置的私有闸门，在没有 Store 锁和 SQLite 事务的匹配阶段暂停。另一线程必须在解除暂停前完成读取或政策变更；有限等待仅用作死锁 watchdog，不以机器速度作为通过条件。该闸门没有公开配置、HTTP 参数或公共 setter。
