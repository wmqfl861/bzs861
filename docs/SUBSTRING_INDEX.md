# 子串候选与派生索引计量（P1-A / P2-B）

## 查询语义与候选

引号短语继续表示原始子串，不改成词序列；ASCII大小写处理和原文字节证据不变。带ASCII片段的短语/字面量先按词级FTS/BM25取候选，再用剩余`max_candidates`预算从原候选路径补足，按文档去重，最终以原`match_score`精确复核及排序。词级优先表达式不是后备层的必选过滤；字段、布尔分支、owner、删除和发布检查保持。

派生gram格式`bzs-ascii-cjk/2+codepoint-grams/2`不保存任何包含CJK码点的窗口，也不跨CJK段拼接非CJK字符。纯CJK依赖原词级位置索引；中英混合叶子使用CJK连续段的必要FTS条件与非CJK gram条件。条件只能扩大候选而不能漏掉精确匹配；最终仍复核原文。非CJK字段超过65,536个不同gram时保留显式overflow标识，不静默截断。

任何候选层未取尽仍返回`partial=true`。这不是无限召回，也不改变只有NOT等查询的有界扫描合同。4001篇≥30KB离线长文档回归及混合字符/符号/布尔测试列入CTest。

## Owner配额与stats

采用审核允许的**独立派生索引配额**，不改变原快照配额或把逻辑字节冒充物理磁盘：

| 字段 | 含义 |
|---|---|
| `content_bytes` / `quota_bytes` | 原快照有效载荷及其限额，语义不变 |
| `substring_index_bytes` | 当前索引行保存的完整序列化gram字符串字节，含字段前缀、空格和overflow标识 |
| `quota_substring_bytes` | `StoreOptions.max_substring_bytes_per_owner`，默认8GiB；当前为Core构造选项，不新增CLI配置参数 |
| `accounted_storage_bytes` | 上述两类逻辑字节之和，不包含所有元数据、词级FTS/WAL/空闲页，不是SQLite文件大小 |
| `substring_index_over_quota` | 旧数据重建或配置降低后，现有索引是否超过新限额 |

写入时在同一事务内预留计量，超过独立限额返回`E_QUOTA`/507；失败不留下新快照、扣费或半个索引。替换、删除、noindex和发布撤回同步调整计量。首次新建文档无需扫描旧全文索引做不可能命中的删除；替换/恢复/撤回仍保留完整删除路径。

旧库重建不因新限额较低而丢弃既有内容，超限状态如实报告。收紧发布限制时，恢复同一事务前已经存在、内容未变的索引行不会新增用量，不能被降低后的配额挡住；恢复此前不存在的索引行仍受配额限制。收据/任务归档等计量属于后续P2-A，本批不声称所有存储都已计费。

## 兼容与重建

业务`PRAGMA user_version`仍为15，产品仍0.1.10。只重建`substring_fts`和可重建的`substring_usage`派生计量表，更新既有设置中的派生索引格式标记。词级分词器仍`bzs-ascii-cjk/2`；不引入unicode61/NFKC/casefold变化。

从原词级标记或gram/1打开时，在一个事务中从当前允许索引的快照重建；失败整体回滚。业务快照、证据、任务、会话及幂等身份不重写。旧二进制不能理解gram/2，会明确拒绝打开，不能回退到旧程序继续写同一数据库。不要手工改标记绕过保护；升级前仍按原备份/隔离政策操作，本批不解除恢复隔离。

## 验证与边界

`gram_index`覆盖CJK/混合/符号/overflow、更新/删除/发布计量、owner隔离、配额回滚、重建回滚和降低配额后收紧发布。`bzs_index_cost CORPUS NEW_DIRECTORY`仅在显式提供的离线语料上创建新测试库，不下载语料，也不删除已有目录。成本比较须同机器、同语料、同编译模式，报告原始失败和最终复测；计时不是SLA。比较的是同语料新建测试库；旧库重建后SQLite可能保留空闲页，文件体积不保证立即缩小。本批不自动执行VACUUM，磁盘回收接续P2-A。

每项validation只保存小型摘要，原始日志不进Git。精确候选尚未取得远端CI时，不能以基线CI或本地测试代替Linux/Windows发布验收。
