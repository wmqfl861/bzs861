## 2. 0.0.2 实际可用范围

本轮继续已有离线链，并修复发现的问题：

`fixture 发现 / 显式本地 HTML、TXT 导入 → 正文提取 → 不可变 SQLite 快照 → FTS / 有界字面检索 → 冻结分页 → 原文证据 → 更新与删除同步`。

保留 `searchd`、通过真实回环 HTTP 调用的 `searchctl`、用户隔离、持久 fixture 任务、租约 epoch、暂停/继续/取消和隔离备份。新增纯配置合同校验的 C++、HTTP 与 CLI 切片。具体操作以 [API 合同](../API.md) 和运行中的 `capabilities` 为准。

仍未提供真实网页搜索源、外网 URL 获取、动态浏览器、递归爬虫、模型执行、语义检索、MCP、多媒体、完整界面或远程 worker。`capabilities` 继续声明 `external_network=disabled`、真实网页来源数为 0、`production_ready=false`；配置校验成功不会改变这些状态。

当前 HTML 解析仍在核心进程内，没有独立解析沙箱；服务只监听回环地址。中文、符号和短语等可使用最多 2,000 个候选的有界扫描，`partial` 表示范围受限，不代表完整中文分析或全量召回。备份继续强制隔离，尚不能安全恢复成可提供服务的状态。详见 [安全边界](../SECURITY.md)。

## 4. 数据库 schema 2 与提取版本

修正候选召回需要更新 FTS 派生索引，因此数据库 `PRAGMA user_version` 从 1 升为 2。`Store::migrate()` 在事务内重建 FTS，只从当前、未删除且允许索引的快照生成 ASCII 候选投影，完成后才提交 schema 版本。新建数据库也使用 schema 2。

本轮迁移测试验证了当前与历史快照、原文证据、冻结会话、任务和统计的保留，以及用户隔离、已删除和 noindex 内容不被错误加入当前索引。迁移拒绝带恢复隔离标志的数据库；比本程序更新的 schema 版本同样拒绝，不能通过迁移绕过恢复屏障。

HTML 解析版本升为 `bootstrap-html/2`。索引迁移不会重新解析或改写已有 `canonical_text`、旧证据或旧快照的 `index_allowed`。若旧快照受旧提取行为影响，需要显式重新导入其授权原始内容，生成使用新解析器的新快照；不能将 FTS 重建称为已经修复所有历史正文或历史发布标记。

0.0.1 程序不识别 schema 2。仅替换回旧二进制不构成可用的降级流程；本轮也没有交付数据库降级工具或安全备份恢复流程。迁移正确性限于已执行的固定样例，不包含断电耐久验收。

依据：[Store 迁移与导入](../../src/store.cpp)、[解析版本](../../include/bzs/html.hpp)、`migrate_schema_one_preserves_records`、`migration_rejects_quarantined_and_newer_databases`。

## 5. 原生配置合同、HTTP 与 CLI

新增 [contracts.hpp](../../include/bzs/contracts.hpp)、[contracts.cpp](../../src/contracts.cpp)，对固定 v1.1 的 `model-config`、`source-manifest`、`search-request` 进行结构、引用、日期、角色能力和可信部署上限检查，并生成独立的规范化副本。测试直接执行 C++，不以调用 Python 参考脚本代替产品实现。

HTTP 操作为 `contract.validate`，只接受 `kind` 和 `config`；服务端提供审核时钟与 `ContractLimits`，不接受请求侧修改时钟或放大上限。结果为：

```json
{
  "kind": "model-config",
  "validated": true,
  "applied": false,
  "effective_config": {}
}
```

以上仅示意结果字段，实际 `effective_config` 由输入与规范化规则生成。`applied=false` 表示没有保存或应用配置、注册来源、读取模型凭据或启用执行能力。

CLI 通过同一鉴权 HTTP 接口调用：

```bash
./build/searchctl validate model-config docs/planning/schemas/model-config.no-model.example.json
./build/searchctl validate source-manifest docs/planning/schemas/source-manifest.example.json
./build/searchctl validate search-request docs/planning/schemas/search-request.example.json
```

本轮实现包含空模型合法、文本角色继承、显式 null 禁用、专门角色缺省禁用、模型默认值、独立角色覆盖、来源审核时间/额度约束、AST 复杂度、字段与操作符匹配、离线范围冲突，以及重复日期条件的 AND 求交与 eq 冲突检查。时间比较保留小数秒精度；配置对象不被规范化过程反向修改。

**这不是通用 JSON-Schema 引擎，也不是完整 v1 搜索执行器。** 额外运行时约束及兼容差异见 [CONFIGURATION.md](../CONFIGURATION.md)，包括：

- 延续严格整数表示：`1` 可以作为整数；`1.0`、`1e0` 不会被隐式转成整数。精确十进制兼容仍是待完成项。
- 模型/来源 endpoint 采用严格的绝对 ASCII HTTP(S) URI，禁止 userinfo、片段、歧义主机/端口和错误转义；条款 URL 可带合法片段。
- 候选来源声明请求配额时也需要配额窗口；已提供的审核日期必须内部一致。未使用的 profile 仍需满足 reasoning 和限额规则。
- 配置审核元数据的真实性、跨配置 profile/source/collection 身份、真实模型能力、执行时授权、DNS/重定向及出站策略尚未实现。
- `search-request` 通过校验不代表整个对象能传给现有 v0 `search` 执行，未索引的字段也不会因此变为可用。

独立合同边界探针记录为 [independent_contract_probe.json](../../validation/takeover/independent_contract_probe.json)，包含 17 个 URI/日期正反例。开发期间发现的 URI 路径字符、重复尾点与 fragment 问题已修正，并复核合法单尾点、IPv6 和百分号编码没有回归。

### 发布核验中的 Windows 日期修正

首次发布后的跨平台复核发现，新合同实现用 `chrono::days` 的计数直接乘 86,400，再赋给 64 位结果。[Microsoft STL 的对应实现](https://github.com/microsoft/STL/blob/da52dc0fcadbd83690cfd1ed32408d2847439493/stl/inc/__msvc_chrono.hpp) 使用 32 位 `int` 作为天数计数类型，因此乘法可能在赋值前溢出；Linux 上较宽的计数类型没有暴露这个差异。这是新合同切片的发布复核发现，不计入前述六类 0.0.1 历史缺陷。

修复在乘法前显式转成 `std::int64_t`，并在既有日期与来源审核测试组中补 8 个断言：1901/2038 两侧的正反区间、0001..9999 年份范围、跨越日界的等价时区时间，以及很早的审核日期和 2038 年到期时间。独立复核已确认转换位置和数值范围；补丁后的实际构建与测试记录见 [date_portability_validation.json](../../validation/takeover/date_portability_validation.json)。原生测试组数仍为 55，断言数增至 269。最初发布的 CTest 日志另存为 [ctest_initial_publication.log](../../validation/takeover/ctest_initial_publication.log)。

首次 Windows Actions 已实际完成依赖安装，并成功编译核心库、`searchd`、`searchctl` 和合同测试程序；核心测试文件中，一条将原始 JSON 代理对字符串直接放入 `CHECK` 宏的写法触发了 MSVC `C3850`。修复将同一个 JSON 解析表达式移到宏调用之前，保留 emoji 比较断言；没有跳过 Unicode 测试。初次失败的提交、运行 ID 和日志片段记录在 [windows_ci_initial.json](../../validation/takeover/windows_ci_initial.json)。两处兼容修复后的本地整合与消毒器结果见 [portability_final_validation.json](../../validation/takeover/portability_final_validation.json)；最终跨平台结果仍须查看修复提交对应的 Actions。

下一次 Windows 运行已通过完整编译、核心测试和配置测试，包含新增日期边界。HTTP/CLI 的 20 项中有 19 项通过，慢请求头测试因 Windows 将服务端超时关闭报告为 `ConnectionResetError` 而出错。测试现同时识别 EOF 和连接重置，保留 8 秒接收超时，并检查关闭至少等待 4 秒，以防立即断开被误认为配置的 5 秒期限生效；超时或其他异常仍使测试失败。同批显式关闭已处理的 `HTTPError` 响应，消除 Python 3.14 报告的测试资源清理警告。此次证据见 [windows_ci_transport.json](../../validation/takeover/windows_ci_transport.json)，本地重测见 [transport_validation.json](../../validation/takeover/transport_validation.json)。

GitHub CI 以 [Actions](https://github.com/wmqfl861/bzs861/actions) 中**最终交付提交对应的实际运行**为准；工作流文件存在、初始化提交的运行或本地 Linux 测试均不能替代该提交的 Windows/Linux CI 结果。
