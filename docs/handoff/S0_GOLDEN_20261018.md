## 2. 黄金查询冻结

文件为 [queries.json](../../tests/golden/queries.json)、[manifest.json](../../tests/golden/manifest.json)、[golden.py](../../python/bzs/golden.py) 和 [test_golden.py](../../python/tests/test_golden.py)。对输入基线逐项比较后，原 40 条记录的 `id`、`query`、`category`、`language`、`good_for` 和原 notes 均保留；只新增数据集身份及 split 元数据。

当前为 **20 development / 15 regression / 5 holdout**，12 条中文、28 条英文。非留出查询在各原分类内按原顺序交替划入 development/regression；h01–h05 固定留出。这个划分发生在本批人工相关性标注和排序评测之前，不能根据后续结果重新分组而沿用原基线。

| 指纹 | SHA-256 |
|---|---|
| `426c431` 原 queries 文件字节 | `06884d3a5457183f9c6542a60c3f98419fc2b42ba3a7ffae5725aa61496cbf75` |
| 原 40 条记录的五个内容字段 | `46b9b603d48e3ebcccf7b1b74dfffbbabfd9f473935fb4536f4903c67b1f6b96` |
| 本批 queries 文件（UTF-8、LF） | `52948aca968cb581e7828988f80a8043f419799938cc1fb6fa54d43a60d2b798` |
| 本批 manifest 文件（UTF-8、LF） | `a9a471b885c5cb04b76d08b1c6a8b0db93334dea14d78f92aa1b7908093391c5` |

manifest 的 `sha256-utf8-lf` 仅兼容 LF/CRLF 检出换行；探测身份仍记录实际文件原始字节 SHA-256，不能用换行归一化掩盖恢复输入变化。原内容指纹按 loader 中明确的五字段 JSON 规范化计算。manifest 另核对 ID 顺序、数量、分类、语言、split 和留出 ID；加载器不会自动生成或修复它。

严格输入限制包含 1 MiB 文件上限、1–1000 条查询、每条文字至多 1000 字符和 4096 UTF-8 字节。固定数据集必须恰好 40 条。重复 JSON 键、重复 ID、非有限数字、非法 UTF-8、未知字段/类型、非法 capability/category/split 以及固定 manifest 不一致会失败。版本和选择上限使用严格整数类型，不接受布尔值或 `1.0` 代替整数。

`load_golden(path)` 返回带 `queries`、实际原始字节 `digest`、`version`、`frozen` 和可选 `manifest_digest` 的对象。旧式只有 `id/query/good_for` 的测试输入继续支持，缺省能力为 web、缺省 split 为 regression，标记为未冻结；同目录存在不属于黄金集的来源 manifest 不改变这个兼容行为。

`select_queries(queries, capability, limit)` 只选择 capability 匹配的非留出记录，按 category 名称排序轮转，分类内保持原顺序，给定相同输入得到相同结果。默认探测上限为每源 8 条；无匹配返回空列表，没有无关能力 fallback。h* 保留 ID 即使出现在旧式输入中也默认留出。开发/回归标签不构成人工相关性标签；manifest 明确记为 `relevance_labels=not_provided`、`ranking_evaluation=not_executed`。

## 3. 探测、恢复和回放

用法与完整边界见 [S0_PROBE.md](../S0_PROBE.md)。候选探测须显式 `--include-candidates` 和非空 `--only`；`--sources` 是清单文件路径。17 条来源登记仍默认禁用，探测路径不修改正常准入，也不写入人工审核结果。

schema 2 报告绑定清单、查询实际字节、黄金 manifest、选项以及解析器代码/依赖身份。计划记录实际选中 ID、查询、分类、语言和 split，逐项区分 pending、reserved、completed、uncertain、skipped；有响应时保存安全元数据、响应体 SHA-256 和至多 10 条完整 hits。响应体以 gzip 存储，核对解压后的字节数与 SHA-256；哈希并非压缩容器的指纹。未执行项保留原因，不从报告里消失。

每次派发前持久预留本次 probe 额度，未知派发结果不自动退款。`--resume` 要求输入、选项与解析器身份一致；completed/uncertain 不自动重发。`quota_scope=this_probe_run` 只覆盖同一次运行，不代表多次 probe 或 searchd 部署日额度已合并。来源的阻断/限流结论优先于早先成功，CLI 存在实际 ok/empty 响应时的退出 0 也不能代表来源审核或 S0 已通过。

`bzs replay` 只读取保存证据并进行离线解析，报告 `network_requests=0`。默认解析器代码与依赖身份必须相同；显式 `--allow-parser-change` 可以比较新版解析结果，但仍报告身份变化与结果差异，不能绕过证据完整性检查。非空输出目录拒绝覆盖；结果仅 passed / failed / no_replayable_rows 中的 passed 返回 0。缺失、损坏或没有可回放样本不能写成一致性通过。

原始响应属于外部不可信输入，也可能包含不适合公开的跟踪或地区信息。raw 样本先本地复核，不默认提交。本批两次云端请求均为 DNS 失败，没有收到 HTTP 响应或正文；经检查只含公共黄金查询和安全错误元数据的原报告与离线回放随摘要公开，未提交锁文件、凭据或原始页面。回放匹配的是两条网络错误状态，不是有效搜索结果样本。解析一致性、来源可用性、条款审核和人工相关性各有独立判断，不能互相替代。

## 4. 静态批量读取与既有基础

`read_many.submit` 只接受调用方列出的 1–20 个 URL，返回持久 job；通过 `job.get`、`job.results`、`job.control` 查看和控制。接口与预算、未知用量、显式失败重试及删除后收据行为以 [API.md](../API.md) 和本批实现为准。MCP 只转发核心操作，不复制业务或权限规则。

本批 schema 4 增加读取任务账本；保留 schema 1、两种历史 schema 2、schema 3 的迁移路径，以及不可变快照、证据引用、删除屏障、冻结会话和隔离备份。正常读取的网络边界不能因 batch 或重试而放宽。静态读取不发现新链接，不能宣称 MAP/ROBOTS/CRAWL 已实现；没有可验证撤销连续性时仍不能把历史备份恢复为可服务状态。

三类原生配置合同的 `applied=false`、严格整数表示等边界继续见 [CONFIGURATION.md](../CONFIGURATION.md)。来源审核、端点/身份/配额匹配在核心和 worker 两侧继续保留；生产代理、remote DNS 和 allow_cidrs 放宽仍拒绝，回环映射只用于受控假网站测试。
