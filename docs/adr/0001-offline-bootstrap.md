# ADR-0001：先实施离线启动切片，不绕过未完成的安全前置

状态：本批实现决策，待独立 review。日期：2026-10-17。

## 背景

蓝图 v1.1 第 14 节要求先完成无网 fixture 链，且明确允许在独立审核尚未完成时进行离线工程准备。当前没有真实模型配置，也没有已核验的免费通用网页来源；用户指定的远程 GitHub 仓库无法在本环境读取。

## 决策

1. 独立目录实现，不能假定远程为空，不覆盖已有工作，不 force push。
2. C++20 业务核心保留；早期 HTTP 用 Boost.Beast，代替尚未可用的 Drogon 候选。这是基础组件选择，不是使用参考成品后端。业务不依赖 Beast，后续可替换传输层。
3. JSON 使用 json-c 引用计数库＋独立词法/UTF-8/重复键检查。所测 json-c 0.18 严格选项对未经转义的中文字符串拒绝，NaN 也需独立拒绝；保留本地可复现负例，而不假定整个上游所有版本都有相同问题。
4. HTML 早期用系统 libxml2 的 HTML 解析器，禁止外部声明，遍历限额，记录解析版本。不是完整正文算法或沙箱；不向公网开放。
5. 数据与正文都在一个 SQLite 数据库内，便于第一条链使用同一事务提交与一致备份。blob 分离、outbox、GC、全局跨介质配额仍未实现，不能将当前实现宣称为 STORE-01 全部完成。
6. FTS5 对支持的普通词项提供候选；最终按自身查询语义复核。符号、中文等不能安全编译的表达式使用有界字面扫描，明确 partial。排序采用简单的已验证词项/标题权重基线；语义及完整排名后续实现。
7. HTTP 只监听回环，CLI 只连接回环；外部抓取、模型、浏览器全部不存在执行路径。网络隔离工作包仍待实现，不以离线开关替代 SSRF 防护验收。
8. 备份文件写入隔离标记，核心拒绝直接服务该文件。独立撤销日志和恢复对账未实现，因此不提供解除隔离的产品接口。
9. 使用 `/api/v0/call` 明示启动合同；不会宣称该子集已经等同于最终 `/v1` 或 MCP 协议。

## 验证边界

Linux 原生构建、C++ 核心、回环 HTTP/CLI、核心 ASan/UBSan 实测；Windows、完整 C++ 配置合同、真实来源、MCP、动态浏览器和独立 review 未通过。完整计划范围不变，未实现能力不公布为可用。
