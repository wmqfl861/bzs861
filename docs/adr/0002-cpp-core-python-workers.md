# ADR-0002：C++ 核心 + Python worker + MCP 适配层

状态：采纳混合架构，2026-10-18 整合澄清。原 S1 决策 D2/D4 的内容保存在接收输入中；本文件同时约束 0.1.1 候选实现，不代表全链路已通过验收。

## 分工

1. `searchd` 保留所有持久数据与业务决策：鉴权、原生合同、来源审核/准入、配额/冷却、查询、聚合、会话、读取策略、缓存、快照、索引、证据和任务。
2. Python worker 处理网络 I/O、来源页面和正文解析；后续加入浏览器与文档组件。worker 不写数据库，并独立执行来源准入与连接层目标检查，不依赖核心传来的“已审核”结论。
3. MCP 层只映射已实现工具，优先 stdio；HTTP/CLI/MCP 共用核心语义、权限和预算。
4. 核心与 worker 通过回环 HTTP JSON 和独立令牌通信。worker 不可用时明确报错，离线检索、配置校验和原文查找仍可用。

使用基础组件符合独立业务实现的要求；不安装或调用四个参考产品后端。0.0.2 的原生合同、角色继承、可信时钟/上限与纯校验 API 继续保留，不能因模型执行排到 S4 而删除。

## 约束与后果

网络检查绑定实际连接、逐跳复核，来源准入在两个进程分别执行。生产代理/DNS/CIDR 放宽模式不满足当前保证，予以拒绝；受控假网站映射仅用于测试。进程边界不等于系统级沙箱，解析隔离与浏览器出口门槛继续保留。

依赖具体版本和平台包按本轮实际环境核对。Python 生态、MCP SDK 或替换存储组件的选择不能代替协议一致性、安全和恢复验收。原计划估算保留为来源记录，补回等效要求后的工量尚未重估。
