# 搜索来源的持久发布限制

本增量在 S2 已有来源准入、缓存和冻结会话上补充持久限制。它不批准来源，默认来源仍全部禁用。来源的可用性、审核及站点正文权限是各自独立的条件。

## 当前规则与历史结果

C++ Store 将显式来源清单的审核合同、当前发布模式和收紧代际保存在数据库中。`links_only` 将搜索命中的标题替换为 URL，并清空摘要；禁用、移除、审核失效或不可缓存的来源撤回旧搜索结果。原 `session.page` 的冻结版本与游标保持，但涉及已撤回来源的会话返回 `E_SESSION_INVALIDATED`，需要重新查询。

这些规则同时约束 `web.search` 的直接结果、短期搜索缓存，以及持久搜索会话。命中由多个来源融合时，只要任何贡献来源要求 `links_only`，整个命中的标题和摘要都受限；无法证明某段文字只来自其他来源时，不重新猜测其归属。没有受影响的来源不使无关会话失效。

每次请求/会话绑定来源策略代际。收紧后即使再放宽，旧结果也保留限制；在收紧前或收紧期间已派发的请求，迟到结果不能跨过限制。完整的新查询可在最新审核允许后生成新结果，不能使旧冻结版本恢复。被撤回的短期缓存会丢弃，当前显式查询通过准入后可以执行一次新的请求；它不重试旧会话或重置旧计费。

源 ID 重用为不同 endpoint、provider、logical service、index family、adapter 或 capability 时，视作新来源身份。旧结果保持撤回，新请求绑定当前身份。

## 重启、到期与配置更新

来源限制、移除记录和代际在重启后保留。审核到期检查在读取结果、提交/派发查询、配置激活及启动时执行。已观察到的到期会持久撤回；后续请求被拒绝或系统时钟回退，不会消除这一事实。续期必须通过明确的新审核清单激活，且只允许新查询。

读取网页的内部调用可以省略来源注册表；省略不会清空已有策略。只有显式的 `{"version":1,"sources":[]}` 清单才会移除全部来源。已有 Store 实例若早于另一实例的清单更新，不能用旧清单覆盖新配置，返回 `E_SOURCE_POLICY_STALE`；应重新打开 Store，再显式激活经过审核的配置。旧 WebService 实例也不能以过时清单派发新查询。

## 存储与升级

schema13 添加 `source_publication_state`、`source_publication_rules` 和 `search_streams.source_generation`。旧 schema12 会话默认代际为0，不改写旧内容。要继续读取旧联网结果，需要明确激活当前来源清单，原合同身份必须与当前来源对应，并通过现时审核与历史撤回检查；缺少当前来源规则时按撤回处理。本地导入和本地搜索会话不受来源规则替代。

规则保留移除来源的代际，最多4096个来源身份；达到上限明确返回容量错误，不通过删除历史屏障腾出空间。当前来源审核合同清单最多1MiB。快照、证据、幂等键、任务计费、原有站点和页面发布限制均继续适用。

## 验证边界

`tests/source_publication.cpp` 使用本机合成 Worker 检查直接结果、缓存、冻结分页、游标、重启、到期/时钟回退、过时配置、源身份变更、多源融合和迟到返回。它不证明真实来源已批准、任意部署故障恢复完成或长期生产容量。来源屏障仍在主数据库中，不是独立撤销 journal；隔离备份的恢复门槛不变。
