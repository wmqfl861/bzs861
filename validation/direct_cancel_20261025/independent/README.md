所有成功执行的输入前后哈希一致。Debug 与 sanitizer 是同一组场景的不同运行，不能累计为24个新产品场景；独立检查也不能加到正式 CTest 套件数中。

## 五项审核发现与闭合

1. 最后成员已经取消、Worker 仍返回正文时，初版仍会无条件提交。现有提交准入检查在无活动成员时只保留合法限制观察，独立原生与 sanitizer 场景已验证。
2. 无可靠 RPC 回包被误标为物理完成，导致最后退出不再协作取消。现在将关闭加入和获得可靠响应分开，未知收据与一次协作取消已验证。
3. `Service` 最终撤权检查的新增收据透传原先覆盖所有带 usage 的操作，现已严格限于 `web.read`；其他操作错误合同保持。
4. MCP 显式空 `read_id` 原先被静默转换为旧式无句柄读取，现只对 `None` 省略参数，无效显式句柄由 Core 拒绝。
5. Worker 重复取消原先刷新退休期限，与新合同不一致。最终实现保留 `previous[0]`，两个精确回归在旧表达式上失败，在修正后通过。

第5项修正发生在独立 RPC v2 执行之后。反向替换最终文件中唯一的期限表达式可精确恢复 v2 已执行的源哈希，因此这里**没有把旧 RPC 执行写成新表达式的重跑**。该最后改动的作者回归及原失败已按原字节保存于 [ttl-author-reviewed](ttl-author-reviewed/archive.json)。作者的相邻执行为37通过、1失败，剩余失败是一个新增 MCP 测试错误读取 HTTP mock 的 `json=` 参数，而实际客户端使用 `data=`；不能称该相邻执行整体通过。后续正式门禁由主整合记录负责。

独立 Worker v1 在创建回环 socket 时被沙箱拒绝，任何业务场景均未开始；[原记录](worker-probe-v1-record.json)和[原异常](worker-probe-v1.log)保留。随后使用正常工具审批取得回环测试权限，未访问公网或付费服务。

## 保留边界

取消与成员成功交付有明确先后，但提交准入检查和 Store 事务之间不持协调锁，因此不承诺回滚已准入的提交。付款方原同步调用可能仍等物理调用结束；HTTP 请求池饱和时取消也可能尚未接纳。句柄及退休控制都不是持久执行/计费账本，不证明跨进程、重启、跨通道共享、网络恰好一次或未知执行可自动重试。

完整工作包、真实来源批准、人审相关性、长期故障和独立撤销连续性不由本目录的有限测试签收。原37 partial / 46 not_started / 0 accepted 保持。
