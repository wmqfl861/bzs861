## 首轮整合失败与更正

`final-v1-ctest` 的27套中有2套失败，原日志、JUnit和输入清单完整保留，详见 `integration-v1-findings.json`。一处是模式逻辑把公开请求的1000毫秒下限误用于会话剩余时间，使合法1秒请求在调度时不能派发；修复后由内部绝对steady-clock期限承载任何仍为正的剩余毫秒，不重启或补足预算。原恢复E2E未修改；作者与独立审阅都保留修前反例及修后结果，早先独立探针对“剩余不足1秒不派发”的错误结论已明确撤回。

另一处是旧搜索测试在共享fixture明确声明links_only时仍期待摘要。保留该fixture与生产权限，改为逐条核对受限结果，并新增独立的明确允许摘要fixture；正反两项均验证真实HTTP及缓存命中。`source_fixture_review`记录独立复核，未以放宽保护解决失败。后续最终门禁使用新命名的 `final-v2` 冻结输入，不把首轮部分通过改写为整合通过。

## 冻结与重放

run_validation.py的--freeze-inputs记录运行时代码、测试、配置、规划执行数据及验证脚本的SHA-256。最终命令在运行前后核对输入，并记录二进制/库摘要、精确argv、环境、退出码和原日志。日志以独占创建防止覆盖；发现源码变化时需要新的命名冻结版本，不能把不一致运行记成最终成功。

纯交接说明与汇总可以在测试后写入，明确从执行输入排除，最终完整源码清单另与实际Git tree绑定。报告不预写包含它的未来SHA，也不预写未来CI成功。最终发布必须非强制更新精确父SHA，核对真实tree和该SHA自己的Linux/Windows结论。

最终门禁包括Linux完整27套CTest（不允许跳过）、15套原生ASan/UBSan且detect_leaks=1、原合同34组、计划守卫13组、只读计划检查、依赖一致性和历史保持检查。真实schema12库由旧静态库生成，升级副本只由最终新库读取，39张旧表旧列内容摘要保持；本机真实HTTP只访问测试回环服务，没有新增外部来源批准。
